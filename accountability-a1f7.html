② How we work now — the rules

Enforced on every message + in my long-term memory. Yours to change.

How we work

  1. Mobile-first, always. Every screen designed + verified at phone width first. Your phone screenshot is the final sign-off — I never call a UI change done until you've confirmed it on your phone.
  2. Plan together, then I execute. For anything non-trivial we agree on the approach before I touch code or data.
  3. Verify before "done." I run the real thing, report what I actually saw, and fix it in every place it lives.
  4. I ask when I'm unsure. A quick question beats a wrong assumption that wastes your time.
  5. Never make you repeat yourself. Accounts, IDs, tokens, deploy paths live in one map I read first.

Hard lines — I never

  1. Send anything to a customer. I prepare it and hand you the link; you send.

  3. Fabricate a number, price, or phone — or guess who a contact is.
  4. Write to a record you're actively editing, or show customer-facing prices on the marketing site.

How I talk to you

  1. Advisor, not a yes-man. Uncomfortable truth first. I own my mistakes instead of praising you for catching them.
  2. Every link clickable; I name exactly where I changed something; no overclaiming.

🔴 Ship-blockers — do these first

BLOCKER Not yet fixed · durable fix

1. An old cached version on your phone silently drops saves

When your phone runs an older cached copy of the app, it sends data the database no longer accepts. The database rejects the whole save — but the app still says "Saved." You price a quote in front of a customer, it looks saved, and later it's gone or reverted. This is the #1 cause of the humiliation you described. (Proven live — Tanisha quote #515, priced 3× and it kept reverting.)

Costs you: vanished prices, "reverting" quotes, looking unreliable to customers.
Fix: force every device onto the current version automatically (no phone can run stale code), AND make a failed save show a red error instead of silently lying. This is the highest-value fix on the whole list.
BLOCKER Not yet fixed

2. "Saved" appears before the save actually succeeds

The success message can fire before the cloud write is confirmed — so even outside the stale-cache case, you can be told it saved when it didn't.

Costs you: silent data loss you don't find out about until it's too late.
Fix: only confirm after the database returns success; on failure, show it and retry visibly.
BLOCKER Code fix landed Jun '26 · re-verify on phone

3. The app can look "logged in" while every save fails

If your login session quietly expires, the app can keep showing you as logged in while every write to the cloud fails in the background.

Costs you: a whole session of work that never leaves the phone.
Fix: tie "logged in" to a real live session; if it's dead, say so and re-auth. A code fix landed in June — it needs one real re-test on your actual phone to confirm.
BLOCKER Migration written · not yet applied

4. Two devices can create the same invoice/job number

You on your phone and the office computer can both mint, say, invoice #401 — two different invoices, one number. (Especially relevant right after tonight's renumbering.)

Costs you: duplicate/confused invoice numbers, bookkeeping headaches.
Fix: let the database hand out numbers atomically. The change is written — it needs to be applied with a two-device test.

🟠 Data & security

DATA/SECURITY Mostly closed · one residual

5. Company list + owner emails readable without logging in

A leftover permission lets the tenant list (company names + owner emails) be read by anyone with the public app key. Your actual customer data — clients, invoices, payments — is already locked down; this residual is limited to owner emails.

Fix: move the one lookup that needs it behind a secure function, then revoke the public read.
DATA/SECURITY Needs hardening

6. Local copy and cloud copy can disagree

The app keeps a copy on the device and a copy in the cloud; under bad timing they can diverge, and a record stuck retrying more than 5 minutes can be dropped.

Fix: one source of truth on sync; stop evicting queued writes before they land.
DATA/SECURITY Done Jul 12 · one decision left

Tonight's cleanup removed the duplicate imports and backfilled the 6 invoices + 8 jobs that were genuinely missing (incl. Al Garone), numbered sequentially so new records continue off the top (next invoice = #400).

🔵 Mobile — it's a phone app, so this is field reliability

MOBILE Ongoing · per screen

The app was largely built desktop-first — several screens squish or run off the edge on a 390px phone (line items, tables, dropdowns, some pop-ups). There are ~288 fixed multi-column layouts and only ~14 phone-specific rules, so this is a real per-screen job, not a one-liner.

Costs you: screens that look broken exactly when a customer is watching.
Fix: go screen by screen — invoices, jobs, quotes, dashboard, client detail, collect payment, schedule, settings — fix each at phone width, and you confirm each on your real phone before it's called done.
