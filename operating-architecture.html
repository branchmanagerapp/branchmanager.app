00 · The core principle

You asked two things that sound opposite. They're not.

On Jul 3 the call was consolidate everything into one account (one M&T, one Plaid, one admin login). Today you're asking to keep the three businesses separate — own accounts, own posting, nothing crossing over. Those only conflict if you mix up two different layers:

Three storefronts. One back office.

Separate everything a customer sees. Consolidate everything you operate behind the curtain. That single distinction resolves the whole tension.

SEPARATE — customer-facing (per brand)

  • Domain & brand site
  • Google Business Profile
  • Social handles (IG / TikTok / FB)
  • Customer email identity & lists
  • Content calendar & posting queue
  • Reviews & local presence

CONSOLIDATE — back office (shared)

  • Banking (one M&T) & Plaid
  • Bookkeeping / CPA handoff
  • Dev + hosting ownership (GitHub / Cloudflare)
  • This ops hub (Branch Manager)
  • Admin logins & secrets
  • Claude / automation tooling

Rule of thumb: if a customer would ever see it, it's separate and brand-pure. If only you touch it, it's shared and boring on purpose.

The tangles that break the "nothing crosses over" rule.
SmartLawn content has landed on branchmanager.app. Historically SmartLawn pages (quote, promos, audit) lived on the tree domain because SmartLawn push-access was blocked. That's a brand leak — a lawn customer shouldn't ever touch a tree URL. Certain (fixed Jul 4 — SL now has its own push access; migrate any stragglers home).
Cloudflare is split across 3 separate accounts under different logins. skateOS (info@2ntr.com), branchmanager/peekskilltree (info@peekskilltree.com), smartlawn (separate). This login can only reach one at a time — fragile and easy to deploy to the wrong place. Certain

Good for the "one back office" plumbing goal — but it means repo hygiene (clear names, no shared secrets) is what keeps the brands logically separate. Certain
Email can't multi-account. The Gmail connector reaches only peekskilltree; info@2ntr.com and smartlawnny@gmail.com aren't reachable together. So per-brand customer email is siloed by necessity, not design. Likely
The clean end state: one Cloudflare account (invite the others as members), repos logically named under one GitHub owner, each brand's pages served only from its own domain, each brand's social/Google/email pure to that brand. Back office merges; storefronts stay pure.

03 · Automated posting — the honest design

It already exists in Branch Manager (SocialBranch). Port it to the other two.

Certain Correction: BM has socialbranch.js — a native scheduler ("replaces SocialPilot"): draft→scheduled→posted, GMB/Meta/IG/TikTok, webhook + OAuth backends. So tree is covered; skate and lawn need their own ported instances. It runs with one non-negotiable guardrail, because of the marketing-email incident:

Draft-and-approve, never auto-fire. The system drafts and schedules posts into each brand's calendar. Nothing publishes to a customer channel until you approve it. No cron that blindly posts. This mirrors the standing rule that all customer-facing messages hit an approval queue first — social is no exception.

Per-brand, identical shape, zero shared queue

1Content inEach brand's engine feeds it: skate = auto-clips, tree = job before/afters + reviews, lawn = install/demo clips. Brand-pure — clips never cross businesses.
2Calendar draftsEach backend (skateOS / Branch Manager / SmartLawn) has its own Content Calendar tab. The weekly rhythm from each brand's marketing plan is the template. Drafts auto-populate; Claude can write captions.
3You approveYou review the week's queue in that brand's hub and approve/edit. One brand, one queue — no chance of a tree post going out on the lawn account.
4Publish to that brand onlyApproved posts publish to that brand's connected accounts (its IG/TikTok/FB via each platform's API or a per-brand scheduler seat). Separate credentials per brand = structurally impossible to cross.

Build once as a shared component, deploy three isolated instances — each wired to its own brand's accounts. Same code, separate wiring. That's how you get "each has its own" without building it three times from scratch.
