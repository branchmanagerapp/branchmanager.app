Square as the back end

How the shop page we already built plugs into Square as its back end — and what is genuinely missing today.
OverviewPricingMigration

The honest starting point

The shop page we built does not take money

I re-read skateos.com/2ntr/shop/ today. Its checkout is titled “Reserve for pickup”, and the page tells the customer: “Online checkout reserves the item; payment is handled at pickup or on the phone.”

So “make it work seamlessly with Square” is not a styling job. The page is a catalogue with a reservation form bolted on. Two things are missing: live stock, and payment.

And its product data is stale by design

The page reads products from the skate Supabase project, which is filled by a manually run sync script. Stock is only as fresh as the last time someone ran it by hand — so the site can happily sell a deck that walked out of the shop an hour ago.

Read those last two rows together and you have the answer. Square gives you no way to rebuild its own website — you cannot inject pages, and the one snippet you get is head-only and skips checkout entirely. But every commerce primitive you need to power your own site is open and working. Square is a bad website builder and a perfectly good back end.

How it fits together

  1. Customer opens your pageThe shop page we already built — same filters, same layout, hosted where you like.
  2. Page asks a small server, not SquareA Cloudflare Worker holds the Square token. The token never reaches the browser.
  3. Worker reads live catalogue and stockSquare Catalog + Inventory APIs. No more manual sync, no more phantom stock.
  4. Customer hits BuyThe Worker creates a Square Payment Link and redirects to it.
  5. Square takes the paymentOn Square's hosted checkout. PCI handled; no card data touches your code.
  6. The order lands in SquareSame place as the 6,838 in-person sales. Same inventory, same payouts, same reports. Nothing changes at the register.
Security, non-negotiable

The Square access token has to stay server-side, in the Worker. It must never be embedded in page JavaScript — anyone viewing source could then read your catalogue, create charges and pull order data. This is the one part of the build with no shortcut.

The work, in order

  1. Turn on stock tracking for the 429 untracked variationsOr exclude them. This is the only true blocker — do it first, in Square, no code needed.
  2. Stand up the WorkerSquare token stored as a secret. Endpoints for catalogue, inventory, and create-checkout.
  3. Repoint the shop page at itSwap the Supabase reads for Worker reads. Filters and layout stay exactly as they are.
  4. Replace “Reserve for pickup” with real checkoutCart totals go to a Square Payment Link. This is the step that turns a catalogue into a store.
  5. Test with a real card, then refund itConfirm the order appears in Square and inventory decrements. Nothing ships until I have watched that happen.
  6. Point the domain and retire the manual syncThe hand-run script goes away for good.
  7. Backfill the 245 missing descriptionsOptional, and it can happen after launch.

The same job on Shopify, for contrast

Shopify would give you storefront, cart, checkout and inventory in one box, with a fully styleable checkout. The cost is that you rebuild the page as a Shopify theme in their template language rather than keeping the HTML we already have, you re-key 1,102 items, you buy new readers because Square's do not work, and you put an untested register in front of a Saturday crowd.

And you would give up your rate

Your measured 2.40% + 15¢ is better than Square's own published free-plan rate. Whatever the reason — legacy pricing or the Premium plan — it is worth protecting. Walking to Shopify Basic means 2.6% + 10¢. On your mix that is a step backwards before a single subscription dollar is counted.

Recommendation

Keep the page. Keep Square. Wire them together with a Worker and Payment Links. You end up with the clean filtered storefront you wanted, live stock, real payments landing in the same system as the register, no hardware to buy, no catalogue to re-key, and no risk at the counter. The single compromise is a Square-branded payment screen at the very last step.
