One Inbox

Why the to-dos felt scattered, and the system that fixes it. Designed from GTD + ADHD-productivity research, tuned to how Doug actually works.

The diagnosis — 7 places, 0 canon

Every overwhelm moment spawned a new surface. As of Jul 5 to-dos lived in: Ground Control's local list · The Plan page · the estimate board · the encrypted to-do dashboard · the To-Do .md on the Desktop · the BM build list in memory · chat itself. Each valid alone, together a maze. The research is blunt: many lists + self-filing = avoidance. The fix is one store, a tiny Today view, and someone else doing the filing.

The design — Claude is the executive function

1Capture — Doug, zero friction (already true)Talk to any Claude session · text people (chat.db) · voicemails (Dialpad→Gmail) · photos → Screenshots folder. Doug never files, tags, or organizes anything. Ever.
2Process — Claude, the secretaryEvery session files into ONE canonical store, updates statuses, mines texts/voicemails weekly, and marks stale items for confirmation instead of letting them rot.
3Store — one, in the cloudA tiny task table on Branch Manager's existing Supabase. Cross-device, Claude-writable, Ground-Control-readable. Replaces GC's per-device localStorage (the root cause of drift).
4Display — Ground Control, and only itToday (≤5 items, Claude-picked, Doug can veto) · Inbox · This week · Parked. The ADHD research is emphatic: more than ~5 visible choices triggers shutdown, so Today is capped.
5Review — weekly, mostly automaticClaude re-mines texts + voicemails + email, refreshes the board and the briefing, retires the done. Doug's part: read the briefing, veto anything.

What lives, what dies

🎛️ Ground Control — THE appThe only thing Doug opens daily. Gets rebuilt on the cloud store (Phase 2).
📋 The Plan — becomes the weekly briefingProse view Claude regenerates from the store. Small on purpose.
🧾 Estimate board — the customer viewNames, numbers, addresses, ages. Claude-maintained from texts + voicemails.
Encrypted to-do dashboard + To-Do .mdRETIRED after their open items are merged into the store. The .md's live info (Dialpad leads, CADCO true balance, Brivo/Gmail fixes) was absorbed Jul 5. Bookmark gets a pointer.
GC's localStorage task listRETIRED in Phase 2 — becomes an offline cache of the cloud store, not a source of truth.
To-dos in chatNever canonical. If it matters, it goes in the store the moment it's said.

Build phases

Phase 1 — merge (done Jul 5)All 7 sources read and reconciled: Dialpad leads → estimate board · CADCO corrected to $22,878 total · Composio marked abandoned (Gmail-native import is the fix) · GL confirmed paid-awaiting-reinstatement · stale statuses flagged for confirm, not guessed.
Phase 2 — the cloud store (Claude's next build)`gc_tasks` table on BM Supabase + lightweight device secret + Ground Control rewired to read/write it. Then any session and any device see the same list, and Claude can file into it directly.
Phase 3 — the rhythmDaily: open GC, see ≤5 things. Weekly: Claude's review + fresh briefing. Monthly: social batch. That's the whole system.
The one rule that keeps it simple forever: no new pages, apps, or lists for tasks — ever. New needs become a section of an existing surface or they replace one. Additions require a deletion.

Research this leans on

GTD's single-inbox + weekly review (David Allen) · Things 3's capped "Today" view · ADHD-productivity findings: visual overwhelm triggers avoidance, choice overload kills prioritization, external structure beats self-organization — which is exactly why Claude plays secretary rather than Doug playing librarian.
